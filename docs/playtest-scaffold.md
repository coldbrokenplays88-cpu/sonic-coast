## Scope

Select **PLAYTEST — SCAFFOLD**, then **OPEN PLAYTEST**. The scene deliberately
contains only a stationary diagnostic marker, fixed camera, status and input
display. Experimental movement is **not implemented**. P/Escape pauses/resumes;
R or Restart resets. The stage selector returns to either existing act.

`src/playtest.js` owns setup, input, update, render, reset, camera and exit state.
Early routes in `game.js` bypass legacy setup, movement, interactions, water,
stage events, bosses, completion, rendering and HUD updates. PLAYTEST uses an
explicit string scene identifier, not an unsupported numeric act or empty level
arrays. Switching clears inputs and discards the diagnostic session. Existing
acts continue through their original stage runtimes. No physics, collision,
level data, character art or cinematic camera code changed.

Changed sources: `src/playtest.js`, selection/lifecycle routes in `src/game.js`
and `src/act2.js`, module startup in `src/main.js` and `src/runtime-manifest.json`.
Presentation: `Inferno-Ascent-Game/index.html`, `style.css`, `README.txt`.
Tests: `test-playtest.cjs`, its module loader in `test-support.cjs`, and the
bounded extracted-package checker `tools/verify-playtest-package.cjs`.
Compatibility JS, `PLAY.html`, hashed runtime and CSS were generated by
`npm run build:player`, not edited directly.

## Opening the game

Player ZIP: extract completely and open `Neon-Express/index.html`. If file launch
is blocked, use the verified local-server method: from that directory run
`python3 -m http.server 8000 --bind 127.0.0.1`, then open
`http://127.0.0.1:8000/`. This requires Python 3; the address is local to the
computer running the command. Windows users can use the supplied
`RUN-GAME-WINDOWS.bat` when Python is installed (not tested here).

A GitHub **source archive** of this branch also includes the same ready-built
game: extract it, enter `Inferno-Ascent-Game`, and open `PLAY.html`. With a local
server use `/PLAY.html`. This source archive is larger than the player ZIP and
